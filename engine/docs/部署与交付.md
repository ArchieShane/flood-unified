# 部署与交付说明

本系统有两种交付方式，**数据都另外提供**，不在源码里，也不在部署包里。

| | 源码方式 | 部署包方式 |
|---|---|---|
| 你拿到 | git 仓库 | 一个目录（或 zip）：两个镜像 + 启动文件 + 说明 |
| 你要装 | Python ≥ 3.11、Docker | 只要 Docker |
| 适合 | 要改代码、做开发 | 只要用系统 |
| 开始 | `scripts/install.ps1`（Windows）/ `scripts/install.sh` | `start.ps1`（Windows）/ `start.sh` |

两种方式装好后，都先跑**快速验证**：一个合成小算例，约 2 分钟跑通一二维全链路，并按质检标准自动判定。它不需要任何数据，用来确认这台机器装对了。

---

## 一、源码方式

### 1. 前提
- **Python 3.11 以上**：开发机用 3.14。Windows 安装时勾选 Add to PATH。
- **Docker**：Windows / Mac 用 Docker Desktop，要先启动；Linux 用 docker engine。
- 能联网：第一次要下载 Python 包和镜像的基础层。

### 2. 安装
```powershell
git clone <仓库地址> drainage && cd drainage
powershell -ExecutionPolicy Bypass -File scripts\install.ps1 -Work D:\swbrain_work\swmm
```
Linux / Mac / Git Bash 用 `bash scripts/install.sh --work ~/swbrain_work/swmm`。

脚本依次做这些事：
1. 建 `.venv`，按 `requirements.lock.txt` 装依赖，装不上时退回 `requirements.txt`；
2. 构建计算镜像 `anuga-swmm:1.0`，约 2 分钟；
3. 没有 `config.toml` 时，从 `config.example.toml` 生成一份；
4. 把一二维工作目录写进用户环境变量 `SWBRAIN_SWMM_WORK`；
5. 跑安装自检（`python -m swbrain.doctor`）；
6. 跑快速验证。

一二维工作目录**必须是纯英文、无空格的路径**，因为 SWMM 不认中文路径。仓库本身放在中文路径下没关系。

### 3. 放数据、填配置
把拿到的数据放在任意位置，然后把路径填进 `config.toml`：

| 数据 | 填到 | 用途 |
|---|---|---|
| 客户雨水管网 GDB 压缩包 `DMT_StormWater_AbuDhabi_Processed.gdb.zip` | `[data].gdb_zip` | 重建一维管网 |
| 同一 GDB 的解压目录（`.gdb` 文件夹本身） | `[data].gdb_dir` | 现状泵站、压力管、出水口 |
| 5 m DTM `AUH_DTM_5m_Z40.TIF` | `[terrain].dtm_path` | 二维地形、井盖标高 |
| 客户热点工作簿目录（`*.xlsx`） | `[data].hotspot_xlsx_dir` | 热点清单 |
| 热点坐标修正 `506 Hot Spots AUH.kmz` | `[hotspots].coords_kmz` | ADM 热点坐标 |
| 客户 22 个水力模型 zip | `[data].client_models_zip` | 汇水区、模型版计算域 |
| 客户水力模型导出目录（含 `SWMM_Export/Mussafah_00.inp`） | `[dmt_model].dir`，以及 `[data].client_swmm_export` = 其下的 `SWMM_Export` | 设计雨型；三态页 |
| Parsons 交付解压目录（含 `Critical Hotspots/` 与 `26092026/`） | `[data].parsons_root` | 规划设施 |
| 运行产物：`out/state/`、`out/summary.json`、`console/data/` 等 | 解压到仓库根目录 | 控制台研判类页签、智能体 |
| 客户数据库（pipe / makani / flood / liveability）的只读账号 | `[source.*]` | 重跑 `python -m swbrain.run` 才要 |
| 本地 PostGIS 输出库 | `[output]` | 同上 |

每项数据分别在哪一步、做什么用，见 `docs/C1_资料清单.md`。填完再跑一次 `python -m swbrain.doctor`，它会列出四种用法各自就绪没有、还缺什么。

### 4. 用
```powershell
python -m swbrain.serve                        # 控制台 http://127.0.0.1:8766/ ，管理端 /admin.html
python tools/c1_pipeline.py check --tag M61    # 一二维：检查数据与每一步
python tools/c1_pipeline.py run all --tag M61  # 一二维：从头跑到交付目录（数小时）
```

## 二、部署包方式

### 1. 前提
只要 **Docker**（Windows / Mac 用 Docker Desktop，并已启动）。不用装 Python。

### 2. 启动
```powershell
cd swbrain-<版本>
powershell -ExecutionPolicy Bypass -File start.ps1     # 第一次：生成 .env 后退出
# 编辑 .env：DATA_DIR（数据放哪）、WORK_DIR（一二维工作目录，纯英文）、RUNTIME_DIR（配置与运行产物），可选密钥
powershell -ExecutionPolicy Bypass -File start.ps1     # 第二次：导入镜像 → 建目录 → 放配置 → 启动 → 自检
```
Linux / Mac 用 `bash start.sh`。

启动后：
- 控制台 `http://127.0.0.1:8766/`，管理端 `/admin.html`；
- 快速验证：`docker compose exec swbrain python tools/c1_pipeline.py selftest`；
- 看日志 `docker compose logs -f swbrain`，停止 `docker compose down`。

交付前可以用 `manifest.json` 核对包是否完整：里面有每个文件的大小和 sha256。

### 3. 部署包：数据怎么放
部署包自带的配置 `config.package.toml` 已经按下面的**固定目录结构**写好了路径。把数据照这个结构放进 `DATA_DIR`，就不用改配置里的路径：

```
DATA_DIR/
  gdb/DMT_StormWater_AbuDhabi_Processed.gdb.zip
  gdb/DMT_StormWater_AbuDhabi_Processed.gdb/          ← 解压出来的 .gdb 文件夹本身
  dtm/AUH_DTM_5m_Z40.TIF                              （连同 .ovr / .aux.xml / .tfw）
  hotspots/workbooks/*.xlsx
  hotspots/506 Hot Spots AUH.kmz
  client_models/OneDrive_1_9-26-2026.zip
  hydraulic_model_export/SWMM_Export/Mussafah_00.inp  ← 客户水力模型导出目录整个放这
  parsons/Critical Hotspots/…  parsons/26092026/…     ← Parsons 交付解压目录整个放这
```

运行产物放进 `RUNTIME_DIR`：
- `out/`：`out/state/`、`out/summary.json` 等；
- `console_data/`：控制台数据（仓库里的 `console/data/`）；
- `exchange/`：交换文件。

**没有运行产物时，服务以「精简模式」启动**：C1 一二维结果页和管理端的计算队列能用，研判类页签和智能体问答要等运行产物放好、重启服务后才能用。

数据库、口令在 `RUNTIME_DIR/config.toml` 里填：
- 本地输出库的主机已写成 `host.docker.internal`，即宿主机；
- 客户库照源码方式填。

### 4. 部署包里的一二维计算
- **在哪算**：服务容器通过挂载的 docker socket，在宿主机上另起 `anuga-swmm:1.0` 容器来算，挂载的是 `WORK_DIR`。
- **怎么发起**：只能在管理端批准计算申请后发起，或在容器里运行 `c1_pipeline.py`。

## 三、口令、端口与安全

- **身份有两种模式**，在 `config.toml` 的 `[identity].mode` 里选，**缺省 `shared_key`，不对接任何平台也照常用**：
  - `shared_key`（缺省）：下面两道共享口令。分不出是谁做的，适合本机、演示和没有统一身份平台的环境。不用装 PyJWT，`[identity]` 段其余各项都不用填。
  - `sdip`（可选）：接 SDIP 统一身份与租户。每人用平台账号登录，按平台授予的职能（`SWBRAIN.VIEW / FIELD / ALERT / PLAN / ADMIN / FEED`）判权限，动作日志与审计记主体号，持有 `SWBRAIN.ADMIN` 就能批准计算申请（含自己提交的，提交人与批准人都留痕）；两道共享口令一律不认。前提：
    1. 平台已按 `docs/SDIP工单_排水智能体接入统一身份.md` 开好客户端、职能与账号，并给了回执；
    2. `pip install "PyJWT[crypto]==2.10.1"`；
    3. 填 `[identity]` 的 `issuer`、`portal_base`、`tenant_id`、`public_base`，客户端密钥放环境变量 `SWBRAIN_SDIP_CLIENT_SECRET`（不写进 `config.toml`）。
    任何一项没配齐，服务启动时直接报错退出，**不会悄悄退回共享口令**。改回 `shared_key` 即恢复原样。
  - 联调自检：`python -m swbrain.identity_check` 查平台侧（签发源、`iss` 是否与配置一致、JWKS、客户端是否已登记、门户是否在线，不要账号）；
    平台开通后加 `--login`（先停服务，浏览器里登录一次），再查令牌受众、交换、租户、会话里的 `SWBRAIN.*` 职能。每项 ✗ 后面写着该找谁。
- **两道口令**（`shared_key` 模式）：
  - `[serve].access_key`：控制台访问口令。设了它，服务才适合给局域网用。
  - `[serve].admin_key`：管理端口令，和访问口令分开；为空时管理端关闭。
  - 口令只写在 `config.toml` 里，不入库、不进镜像。
- **端口**：
  - 源码方式：设了 `access_key` 时服务监听所有网卡，没设时只监听本机。
  - 部署包：缺省只映射到 `127.0.0.1`；要给局域网用，把 `.env` 的 `BIND` 改成 `0.0.0.0`，并先设好 `access_key`。
- **大模型密钥**：只放在环境变量里，或部署包的 `.env` 里，永远不写进 `config.toml`。

## 四、常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| PowerShell 运行 `.ps1` 报解析错误 | Windows PowerShell 5.1 按本地编码读脚本 | 用仓库里的脚本（UTF-8 带 BOM），不要另存成无 BOM 格式 |
| `CRSError` / 「proj.db … another PROJ installation」 | 机器上还有别的 PROJ（如 PostGIS 自带的） | 流程脚本和快速验证会自动指向 rasterio 自带的 PROJ；自己写脚本时设 `PROJ_DATA` |
| SWMM 打不开 `.inp`、报路径错 | 工作目录里有中文或空格 | `SWBRAIN_SWMM_WORK` / `WORK_DIR` 改成纯英文路径 |
| Git Bash 里 docker 挂载路径变成 `C:/Program Files/Git/…` | Git Bash 会改写以 `/` 开头的参数 | 命令前加 `MSYS_NO_PATHCONV=1` |
| 启动日志「精简模式」 | 没有运行产物 | 放好运行产物后重启 |
| 管理端「管理端没有开」 | `admin_key` 为空 | 在 `config.toml` 设一个，重启服务 |
| 智能体回答里提示用了规则规划器 | 没有大模型密钥 | 设 `DEEPSEEK_API_KEY`（或 OpenAI） |
| 快速验证某项 ✗ | 看 `out/demo/verify.json` 的数值和标准 | 计算没跑完多半是 docker 没启动或镜像没建 |
