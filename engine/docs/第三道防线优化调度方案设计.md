# 第三道防线优化调度方案（v2）：业务场景、模型与实现

> 客户定义的第三道防线：暴雨事中，靠**移动泵站及其运输车辆、人员、物资**临时处置积水点。本文三部分：① 业务场景（DMT 值班怎么干活，决定模型要长什么样）；② 优化模型（对象、变量、目标、约束、求解）；③ 已实现的 v2 求解器与结果、模拟参数、待客户替换的数据。
> 状态：v2 已实现并在 10cc 情景真机验证（2026-09-22，`swbrain/dispatch2.py`、`swbrain/resources.py`，配置 `[dispatch].solver = "v2"`）。

## 0. 一句话

在滚动的时间轴上，为每个积水点选一个**处置包**（泵型与台数 / 罐车数 / 接力级数），为处置包配**运输车次、班组与物资**，走**时变路网**，在目标时限内把**加权积水时长**压到最低，同时把钱花在刀刃上（费用进目标函数，给出「最快 / 平衡 / 最省」三个帕累托方案）；并把「单点最优 vs 全局最优」的差价算给客户。

### 1.3 现场作业怎么做（决定服务时间与约束）

1. **运泵**：泵不是自己跑的。12 寸柴油泵一车一台（带吊装），8 寸一车两台，6 寸三台一组一车；一辆车送到卸下（10 min）返回再装（10 min），90 min 窗口内一辆车通常跑 2 趟。重型车不能走水深 ≥0.45 m 的路，轻型 ≥0.30 m；限重桥另算。
2. **架设**：到位后接吸水管、铺排水软管到排放去处。排放去处 300 m 内直排；300–1,500 m 需**接力**（每 100 m 一级，每级排量 ×0.85，每级多一次架设）；1.5 km 内没有可接纳的排放去处（出水口 / 泵站 / 渗井）就只能**罐车拉走**或等管网退水。
3. **抽排**：泵按额定排量抽；入流大于在场排量时水位不降——这类点先封路疏散、雨峰后再派。退干时刻由**退水重演**算（净入流 + 自然去水 + 泵，5 min 步长）。
4. **人**：12 寸泵 3 人、8 寸 2 人、6 寸组 6 人（含司机 / 操作 / 看管）；夜间加照明、加 1 人；连续工作 ≤12 h，之后需换班。
5. **物资**：软管（每台 50 m 基础 + 每级接力 100 m）、燃油（12 寸 25 L/h、8 寸 12、6 寸组 18）、发电机与照明、封路的路障与标志、沙袋。
6. **罐车**：4,500 gal（17 m³），装 10 min、卸 10 min、往返按 30 km/h；同一点最多 6 辆。
7. **钱**：泵台时（12 寸 90 / 8 寸 60 / 6 寸 36 AED/h，最短 4 h）+ 动员费 500/台 + 人工 35 AED/人·h + 车公里（重 4.0 / 轻 2.5 AED/km）+ 柴油 2.6 AED/L + 罐车 250 AED/h；夜班 ×1.25。

### 1.4 值班工程师要回答的问题（模型的输出）

- 现在能压住多少个点、哪些压不住、为什么（入流 / 无排放去处 / 行程 / 人手 / 车次 / 预算）。
- 每台泵、每辆车、每个班组什么时候从哪出发、到哪、几点开抽、几点退干、之后去哪。
- 三个方案（最快退水 / 平衡 / 最省钱）各多少钱、多压几个点、III 级达标几个。
- 人手、车次、软管、燃油、罐车够不够；哪个驻地缺、缺多少；12 h 后要换多少人。
- 某个点要单独最优（比如指挥点名的隧道）要从全局单里抢谁的泵、推迟谁、多花多少钱。
- 现场报「已退干」「泵坏了」之后，方案怎么变。

## 第二部分 · 优化模型

### 2.1 对象（本体层）

| 对象 | 关键属性 | 数据来源 |
|---|---|---|
| **FloodPoint / FloodState** | 位置、过程线（体积 / 入流随时间）、等级、优先级、目标时限、排放去处与距离、接力级数、可派性 | 本系统按情景生成（客户热点 × 管网缺口 × DTM）【推演】 |
| **PumpUnit** | 型号、额定排量、架设时间、班组人数、重量、车型等级、台时单价 | 数量来自客户预案 A【实测】；排量 / 架设 / 人数【假设】 |
| **Vehicle** | 车型等级（重 / 轻）、载量（各型号一车几台）、速度、AED/km | 【模拟】：每 2 台泵 1 辆车 |
| **Crew** | 人数、当班 / 可召回、班次、交接 | 预案 A 人数（ADM 265 / DRM 588）【实测】；AAM 无数按每台 2.5 人【模拟】；当班 50%【模拟】 |
| **Depot** | 位置、泵 / 车 / 人 / 物资库存、罐车数 | 民防站位置【实测】；几个片区归到同一最近民防站合成一个驻地 |
| **Material** | 软管 m、燃油 L、照明套、路障套；消耗系数 | 【模拟】 |
| **Tanker** | 数量、容量、周转 | 数量预案 A【实测】；容量【假设】 |
| **DisposalSite** | 出水口 / 泵站 / 渗井终点，是否在常规雨下超载 | 管网终点【实测】 |
| **RoadState** | 时变路网：积水路段加罚 / 断开（按车型水深阈值） | 宜居库 41 万段路网【实测】 + 情景水深【推演】 |
| **Package** 处置包 | 派什么派几台（或几辆罐车）、预计到位、退干时刻、积水时长、延误、台时、人数、软管、燃油、费用 | 每点枚举 ≤12 个，用重演算好 |
| **Assignment** 派单 | 泵 / 罐车、驻地、车次、班组人数、出发 / 到达 / 开抽 / 退干、软管、燃油、费用 | 求解输出 |

### 2.2 决策变量（每个滚动窗口）

- `y[p,g] ∈ {0,1}`：点 p 采用处置包 g。
- `n[c,p] ∈ ℤ₊`：**单元类** c（同驻地、同型号、同可用时刻的泵合成一类；罐车按驻地一类）派到点 p 的台数。533 台泵 → 几十个类，模型小得多；解完再把类展开成具体编号。

### 2.3 目标函数

```
min  Σ_p w_p · [ Σ_g H_pg · y_pg + H_p0 · (1 − Σ_g y_pg) ]     加权积水时长（H_p0 = 不处置时）
   + α · Σ_p w_p · Σ_g delay_pg · y_pg                          错过目标时限的加权延误（α = 1）
   + (1/V) · [ Σ_p Σ_g cost_pg · y_pg + Σ_c Σ_p tcost_cp · n_cp ] 费用（包费用 + 车公里与司机工时）
```
分派项另加 `w_p · (行程 + 等待)/60`（到达越晚积水越久，按包平均台数摊到每台），让求解器优先派近的类，也让单点最优放大权重后自然选最近的泵。`w_p` = 优先级（等级 × 重要度 × 重点单位）；`V` = 「一个优先级·小时的积水值多少 AED」：**最快 1,000 / 平衡 100 / 最省 10**，三档解三次 = 帕累托三点。单点最优：把该点 `w_p × 10⁴` 重解，差就是抢泵代价。可选预算上限 `Σ 费用 ≤ B`。

### 2.4 约束

| 约束 | 表达 |
|---|---|
| 每点最多一个包 | Σ_g y_pg ≤ 1 |
| 型号平衡 | 对每点每型号 m：Σ_{c∈m} n_cp = Σ_g need_gm · y_pg |
| 类容量 | Σ_p n_cp ≤ count_c |
| 行程上限 | n_cp 只在 travel_cp ≤ 上限（III 级 120 min、其余 90）时存在 |
| **班组人数**（按驻地） | Σ_{c∈d} crew_c · n_cp ≤ 当班 + 可召回 |
| **车次**（按驻地、车型） | Σ_{c∈d,v} n_cp / carry_c ≤ 车辆数_dv × 每窗口趟数 |
| **软管**（按驻地） | Σ_{c∈d} (50 + 100·级数_p) · n_cp ≤ 库存 |
| **燃油**（全网） | Σ fuel_pg · y_pg ≤ 库存 |
| **罐车池**（按驻地） | 罐车类容量 |
| 预算（可选） | Σ 费用 ≤ B |

### 2.5 求解流程

1. **可行性分诊**（每窗口重算，`dispatch.feasibility`）：t 时刻的体积与入流、排放去处、接力、需排量 → 可派 / 罐车 / 封路等待。
2. **处置包枚举 + 重演**（`dispatch2.point_packages`）：单型号 1–3 台、双型号混合、罐车 2/4/6 辆；每包用 `replay` 算退干时刻、积水时长、延误、台时、人数、软管、燃油、费用。非线性在这里预先算掉。
3. **窗口 MILP**（`dispatch2.solve_window`，scipy HiGHS）：10cc 第 1 窗口 172 个候选点、几十个类，约 1 s。
4. **解码 + 实际到达重演**（`decode`）：类 → 具体泵编号；按实际行程与架设重演，得每台的出发 / 到达 / 开抽 / 退干。
5. **滚动**（`rolling`）：每 60 min 一个窗口、8 个窗口；抽干的泵在原地释放；入流已低于在场排量 30%、剩余水量 30 min 内抽完的点释放多余泵（抢占）；上一窗口「入流压不住」的点雨峰后重新进候选。
6. **车次与班组排程**（`schedule`）：按驻地把同去向的泵拼车（载量）、车辆轮转（送到 + 卸 + 返回 + 装）；当班先上、召回的晚 60 min；泵工作 >12 h 记换班人数；车次等待加到出发 / 到达 / 退干上。
7. **校核与并排**：调度单再过 `replay_plan` 得全网时间轴与 KPI；与贪心基线、客户预案 A 就地、Parsons 2027 临时方案并排（沿用）。
8. **帕累托**：三个 V 各跑一遍（结果缓存），页面与对话框给三方案表。

### 3.2 10cc 情景结果（2026-09-22，决策时刻 210 min，三家市政 21 个驻地 / 463 台泵 / 476 辆罐车 / 911 人）

| 方案 | 费用 AED | 压住点数 / 374 | 泵 | 罐车 | 人员 | III 级达标 / 42 | 首台到位中位 |
|---|---|---|---|---|---|---|---|
| 最快退水（V=1000） | 651,150 | 128 | 165 | 216 | 523 | 5 | 54 min |
| **平衡（V=100）** | **369,281** | **123** | 172 | 44 | 511 | 5 | 74 min |
| 最省钱（V=10） | 243,809 | 108 | 153 | 0 | 473 | 4 | 61 min |
| v1（三波，仅 ADM） | 278,098 | 58 | 33 | 165 | — | 2 | 14 min |

**集中调度 vs 承包商各管各的（平衡目标）**：各管各的压住 120 点 / 477,632 AED；集中调度压住 123 点 / 512,378 AED，跨区调 71 台（工单费 2,000 AED/台 = 142k）。多压住 3 个点、多花 3.5 万——因为人手才是瓶颈，把泵跨区调过去意义有限；真正的杠杆是跨区调人和罐车。这个数字正是 DMT IT 要的「集中资源可见性与调度」的量化依据。

读法：
- 从最省到平衡：+125k AED 换 +15 个点、+1 个 III 级达标；从平衡到最快：+282k 只换 +5 个点，钱主要买了 216 辆罐车。**平衡是推荐档**。
- **人手是硬约束**：阿布扎比岛侧三个驻地的班组全部用满（92/92、84/84、34/34），泵只用了 30%；当班 455 人对平衡方案需 511 人，要提前召回 56 人。这是模型第一次把「泵多人少」量化出来。
- 加权积水时长三方案只差 0.08%——这个指标被 194 个「压不住」的点（入流大于可派排量 56 / 无排放去处 31 等）主导，泵解决不了，要靠第一道（换管 / 调蓄）和第二道（预置）。
- 42 个 III 级点只有 4–5 个能在目标时限内排干（需 9 级接力的点必然超时）。
- 求解耗时：三方案合计约 30 s（上下文热），冷启动含路网矩阵约 100 s。
