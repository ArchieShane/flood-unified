# 控制台交互设计（2026-09-20 重构）

## 为什么重构

前几轮一直往页面里加功能，出现了四个问题：七个页签放不下一行；「预置与应急」一页里塞了第二道、第三道、客户清单对照、算法对照、87 行调度单，要滚很久；顶栏挤着生成信息、重现期开关、一长串状态文字；地图右上角七个图层复选框与左下角越来越高的图例互相抢地方。求解器/贪心基线、加权积水小时这类内部词汇直接摆在首屏。

## 骨架：按客户的三道防线组织

| 页签 | 内容 | 进页签时的图层预设 |
|---|---|---|
| 总览 | 现状六格 → 三道防线三张卡（点卡进入）→ 承诺句 → 折叠的就绪度 / 片区排序 / 专家控件 | 片区风险、瓶颈管段、建议点 |
| 第一道 基础设施 | 子页签：建议 / 排期 / 达标分期 / 剩余风险 | 建议：片区 + 建议点；排期同；达标分期：片区 + 瓶颈；剩余风险：只留剩余风险 |
| 第二道 预置 | 预警等级分段控件 → 三格结论（比事后调度省多少、III 级处置 5→55、到位时刻）→ 预置价值说明 → 四级对比表 → 预置驻地（默认 6 行，可展开） | 客户热点、预置驻地、积水区 |
| 第三道 应急调度 | 决策时刻控制条 → 四格结论 → 分诊条形图 → 调度单（默认 12 行，可展开）→ 折叠的算法对照 / 客户清单对照 | 积水区、驻地与派车、客户热点 |
| 数据与可信度 | 可信度边界置顶 → 折叠的数据来源 / 怎么算 / 当场算 / 复核方法 | 片区风险 |

旧的深链接 `?tab=props|sched|standard|residual|dispatch` 仍可用，自动映射到新页签；`?tab=line3&fp=ADM-62` 直接打开某个积水点的弹窗。

## 通用模式

- **结论先行**：每页顶部是三到四格大数字（`.kpis`），细节表往下放；内部指标（求解器 vs 贪心、加权积水小时、波次耗时）进 `<details class="sec">` 折叠块。
- **长表默认截断**：调度单 12 行、预置驻地 6 行、片区排序 10 行、建议 30 条、排期每组 8 步，底部「展开全部（还有 n 条）」。
- **来源与假设不抢首屏**：积水点与泵队来源、世界模型/本系统说明收进「积水点与泵队的来源」折叠块，标题右侧只留「本系统 / 预测侧模型」一个词。
- **地图跟页签走**：`PRESET` 表定义每个页签打开哪些图层；图层面板可折叠（标题显示已开数量）；图例只画已开图层，超高时内部滚动。
- **弹窗分层**：标题行（编号 · 级别 · 客户重要度）→ 关键数字网格 → 「怎么算出来的」折叠 → 退水重演（两条曲线 + 表 + 手动派泵）。
- **顶栏只留两件事**：标题与生成信息（设计雨强移到悬停提示）、重现期开关（状态压成一行，详细说明在 ⓘ 里）。
- **按钮有反馈**：「重解」点击后变灰显示「计算中…」，算完再恢复。

## 词汇

首屏只用客户能读的词：处置点数、关键点按时、积水时长、首车到达、按客户目标退干、III 级点得到处置。算法名与手册条款号只出现在折叠块和数据与可信度页。
