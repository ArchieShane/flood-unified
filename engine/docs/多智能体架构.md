# 多智能体架构（2026-09-30 落地）

> **总览与「为什么这么设计」已合并到 `docs/智能体架构.md`**（2026-10-02）：本体与智能体的关系、五个智能体、
> 分派规则、两条入口（控制台 / Harness 原生页）、子智能体现状，都在那篇。
> 本文只留**运维细节**：大模型怎么配、权限与审批、管理端各页签、接口清单。

控制台对话抽屉、管理端「试问一句」、`/api/agent` 都先到**主智能体**，由它分派给四个专业智能体之一（一句话问了两件事就分给两个），再把回答汇总。每个智能体只能调自己名下的本体动作；会起计算的事只能申请，由管理员在管理端批准。

## 五个智能体

| 智能体 | id | 规划器 | 名下动作 | 管什么 |
|---|---|---|---|---|
| 主智能体 | `orchestrator` | 大模型分派（`delegate` 工具）→ 规则 | 无 | 判断问题该给谁、汇总回答、记轨迹 |
| 调度研判 | `dispatch` | DeepSeek Harness → 大模型 → 规则（= 原来的排水智能体） | 原有 41 个 | 三道防线：退水时间与手段、派泵、全局调度、预警、汇水区 |
| 一二维计算 | `hydro` | 大模型 → 规则 | `hydro_cases` `hydro_result` `hydro_progress` `hydro_submit` | 各情景 / 各态结果、计算进度、提交计算申请 |
| 报告交付 | `report` | 大模型 → 规则 | `delivery_status` `report_submit` | 交付目录与报告、申请重出交付 |
| 数据质检 | `qa` | 大模型 → 规则 | `qa_data` `qa_results` | 数据与环境齐不齐（能否复现）、每个态的结果质检 |

动作归属写在 `swbrain/ontology/schema.py` 的 `ActionType.owner`；实现在 `swbrain/ontology/actions/hydro.py`。
Harness 原生 Web UI 侧另有四个预设与它们一一对应（`agent/dsh/presets/{drainage,hydro,report,qa}/`）。

## 大模型（2026-10-01）

- `[agents].llm = true` 且密钥在时，主智能体和三个专业智能体都用大模型。端点、模型、密钥变量可以在 `[agents]` 里单独写（`api_key_env` / `base_url` / `model`），缺省沿用 `[agent]`。本机用 DeepSeek 的 Anthropic 兼容端点 `https://api.deepseek.com/anthropic` + `deepseek-flash`。
- **主智能体**只给大模型一个工具 `delegate(agents, reason)`，强制调用；端点不收强制 `tool_choice`（deepseek-flash 的思考模式回 400）就不强制再试一次。只认启用了的智能体、最多两个，理由写进轨迹（`route[].by = "llm"`）。思考型模型先想再调工具，`router_max_tokens` 缺省 2000，太小会在调 `delegate` 之前截断。
- **专业智能体**的工具只有自己名下、管理端没停用的动作，不带取对象 / 查对象集这类通用工具；人设是注册表里的 `prompt` + `role`。清单外的工具名（模型臆造的、别的智能体的）一律拒。
- **申请动作加闸**：话里没有「提交 / 申请 / 重算 / 跑一下」这类词，大模型调 `hydro_submit` / `report_submit` 也会被拒，和规则规划器同一条判据。
- **任何一步出错都退回规则**：没密钥、网络、鉴权、没调 `delegate`、给了不存在的智能体……分派退回下面的规则分派，专业智能体退回规则规划器，原因写进回答的 `note` 和轨迹。`llm = false` 全部走规则。
- 实测（2026-10-01，deepseek-flash）：12 句分派对照里 12 句和预期一致，单次 1.6–4.6 s；四个专业问题都调对了动作，数字与 `out/c1_stats_M61.json` 一致，单次 4–7 s。

## 分派规则（`swbrain/agents/orchestrator.py`）

大模型不可用时用这套；有大模型时它是兜底。

- 每个专业智能体有一组**领域词**（管理端可改）。至少命中一个领域词，才会把问题交给它；名下动作的意图词只用来加分。这样「检查井」「调度结果」这类说法不会被抢走。
- 情景名（模型版 / M61 / R61 / D24 …）只算上下文，单靠它不构成去处：「模型版的交付目录在哪」只交给报告交付。
- 问 Mussafah、29.RB2、Madinat 的 L1 / L2 方案，或问「C1 模型版由哪些汇水区组成」这类汇水区问题，都留给调度研判。
- 一句话同时命中两个智能体的**核心**领域词（例：「算完了吗？质检过了没有？」），两个都分，最多两个。
- 都没命中，交给调度研判兜底。每次分派的理由写进轨迹。

## 权限与审批

- 两个申请动作（`hydro_submit`、`report_submit`）只在话里明确说「提交 / 申请 / 重算 / 跑一下」时才调用，并且只写一条待批准的申请（`out/agents/jobs/<id>.json`），不起计算。
- 管理员在管理端点「批准」后，才起一个**独立的**执行进程（`python -m swbrain.agents.computejobs _exec <id>`）跑 `tools/c1_pipeline.py`。独立进程的好处是：控制台服务重启不会打断计算。
- 同时只跑一条申请，后批准的排队，前一条结束后自动接上。
- 暂停 / 恢复用 `docker pause` / `docker unpause`，保留进度；取消会停掉这条申请起的容器（`c1pipe_<tag>_<态>`），已算的进度丢失。
- 管理端停用的动作，在本体执行入口 `Runtime.act` 就被拒绝，DeepSeek Harness 经 MCP 调来的也一样。
- DeepSeek Harness（MCP 工具清单）和调度研判的大模型 / 规则规划器，只看得到调度研判名下的动作。

## 管理端（`/admin.html`，控制台顶栏「管理端」）

- **口令**：`config.toml` 的 `[serve].admin_key`，和控制台访问口令 `access_key` 分开。
  - 为空时管理端关闭，接口一律 403。
  - 登录后种 12 小时的 HttpOnly cookie；连续输错 5 次锁 10 分钟。
- **智能体**：职责、当前规划器（调度研判显示 DeepSeek 的模型名）、调用次数 / 最近一次 / 平均耗时 / 失败步骤。可以改三样：启用 / 停用智能体、启用 / 停用单个动作、分派关键词。改动存 `out/agents/overrides.json`，即时生效，「恢复缺省」删掉覆盖。
  - 模型与人设不在这里改：调度研判的模型在 `[agent.dsh]`，人设在 `agent/dsh/presets/`；另外三个和主智能体的模型在 `[agents]`（缺省沿用 `[agent]`），人设在 `swbrain/agents/registry.py`。
- **会话与轨迹**：每次对话的问题、分派给谁与理由、每个智能体调了哪些动作（成败、耗时）、回答。可按智能体筛、按问题搜；「试问一句」可以现场测分派。数据在 `out/agents/sessions.jsonl`。
- **计算任务**：
  - 上半部分是机器上正在算的全部一二维容器，包括命令行后台链起的，只读：进度、剩余时间粗估、暂停状态。
  - 下半部分是申请队列，可以批准、驳回、暂停、恢复、取消（页面内二次确认），也能看执行日志。每 30 秒刷新一次。
- **操作记录**：管理员的每次登录、改配置、审批，记在 `out/agents/admin_audit.jsonl`。

## 接口

| 接口 | 说明 |
|---|---|
| `GET/POST /api/agent` | 对话（多智能体开着就走主智能体；`[agents].enabled = false` 退回单个排水智能体） |
| `GET /api/agents` | 智能体清单（公开给控制台，只读） |
| `POST /api/admin/login` · `logout` · `GET whoami` | 管理员登录 |
| `GET /api/admin/agents` · `POST agent` · `POST agent_reset` | 智能体状态与配置 |
| `GET /api/admin/sessions` | 会话与轨迹 |
| `GET /api/admin/jobs` · `POST job` · `GET job_log` | 计算任务 |
| `GET /api/admin/audit` | 操作记录 |
