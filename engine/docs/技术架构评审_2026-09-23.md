# 技术架构评审（2026-09-23）

对象：仓库 `D:\阿布扎比\排水智能体`，提交 `409038e`（64 次提交，2026-09-16 至 09-23，8 天）。方法：逐模块读代码与度量（行数 / 字符数 / 函数数 / 异常处理 / 耦合 / 测试引用），结合本轮在真机上的运行观察（预热、求解耗时、并发卡死事件）。没做压力测试和渗透测试。

## 0. 结论

这是一个**领域建模很扎实、工程骨架仍是原型**的系统。

- 扎实的部分：以积水点为核心的本体（14 对象 / 22 关系 / 23 可执行规则 / 34 动作）、情景目录、两代调度求解器、6 个外部数据契约、把「模拟 / 假设 / 占位」写进载荷和回答里的纪律、源库只读的硬保证、密钥只走环境变量、139 个 5 秒跑完的测试、15 份文档。
- 原型的部分：单进程单状态（`serve.State` 把一切装在内存里，重启要 13–15 分钟预热）；全局一把锁 + GIL 让长求解（60–110 s）期间整个服务失去响应（本轮实测过一次卡死）；`serve.py` 用 if 链分发 30 个接口，`runtime.py` 1,961 行、161 KB、148 个函数是一个上帝对象；控制台是一个 193 KB 的单文件，72 个函数手拼字串；口令随 URL 出现在日志里；测试全是合成夹具，没有一条对真实状态文件的集成测试，没有 CI。

**判断**：够支撑 PoC 演示和单值班员试用，不够支撑多用户、7×24 的运行。下面按严重度列问题，再给分三期的改法；近期这一期不改总体结构，两周内能做完。

## 2. 做得对的地方

1. **本体是系统的脊柱**：算法模块的输出都被物化成对象与关系，规则可执行且带出处，动作是智能体唯一能做的事（没有自由 SQL、没有自由文件访问），加动作三步走，文档表格自动生成。这条纪律让 8 天里加 34 个动作没有失控。
2. **可信度纪律**：`simulated` 标记贯穿资源、桥梁、承包商、路况、历史经历；回答里明说「推演估计」；源库会话级只读；密钥只从环境变量（含注册表兜底）读；客户数据不进仓库（`.gitignore` 排除 `out/`、`exchange/*`、`config.toml`）。
3. **契约先于数据**：六个外部源同一套形状、拉推两条路、契约校验、示例文件；客户数据没到，接口先到位（导入器已备好）。
4. **求解器设计**：处置包 + 单元类聚合把 463 台泵 × 845 点压成可解的 MILP，滚动窗口、重规划锁定、压力测试、鲁棒期望都是在同一框架上加系数，没有另起炉灶。
5. **中英双语与文档**：界面词典 + 数据侧 `_en` 字段；15 份文档覆盖设计、接口、可信度、演练、评审。

## 3. 问题清单（按严重度）

### A. 运行架构

**A1 单进程内存态，重启即重算（高）**
`serve.State` 装载 `out/state` 后，情景上下文、调度载荷、世界模型对照、路况全在进程内存字典里，没有落盘。每次改代码重启都要 12–15 分钟预热；进程崩溃等于全部重来；无法多实例。本轮为改一行摘要文字重启了 6 次，每次十几分钟不可用。

**A2 一把全局锁 + GIL，长求解期间整个服务失去响应（高）**
`dispatch_at` 在 `self.lock` 内做 60–110 s 的求解；预热线程也拿这把锁；HiGHS 的 Python 包装与 pandas 重演都握着 GIL。实测：把帕累托三路改成线程并行后，单核饱和、进程 88 线程、`/api/ontology` 这样的轻接口 20 秒不响应、一个请求 30 分钟没回。现在的顺序版只是把问题缩小到「求解时别的请求排队等锁」，没有解决。没有任务队列、任务 id、进度或取消。

**A3 serve.py 同时是 HTTP 框架和业务编排（中）**
30 个接口用 `if u.path == ...` 链分发，参数解析散在每个分支里（`float(qs["t"][0])`），错误统一 `except Exception → 500 + 前 300 字`。没有路由表、没有参数校验层、没有接口描述（OpenAPI）。加一个接口要改三处（serve、runtime、console）。

**A4 runtime.py 是上帝对象（中）**
1,961 行装了：对象装载、缓存、关系解析、规则求值、34 个动作及其中英摘要（每个动作 `_act_` + `_sum_` 两个方法，摘要里手拼两种语言的长句）。148 个函数在一个类里，单个动作很难单独测试；`schema.py` 里规则的「逻辑」是人写的说明字串，和代码实现是两份，靠 `consistent` 比对兜底。

**A5 控制台单文件（中）**
193 KB 的 HTML，72 个函数，模板字串手拼 + 手动 `esc()`，状态是全局变量（`DP`、`RP`、`V2OBJ`、`GANTT_VIEW`）。没有构建、没有模块、没有测试（只有 `node --check`）。已经踩过两次坑：函数名撞车（`aed`、`bars`）、词典键含点被 `t()` 拆开。再长就改不动了。

### B. 数据与状态

**B1 状态没有版本（中）**
`out/state` 由 `run.py` 批处理生成，服务装载时不知道它来自哪次运行、哪份配置、哪个提交；配置改了阈值不会让缓存失效。`exchange/` 是集成面，校验是手写的 `validate()`，没有 JSON Schema 文件，版本只有一个字串。

**B2 配置与缺省值双轨（中）**
784 行 toml 混装工程常数、假设参数、服务设置；代码里又有五处 `DEFAULTS` 字典（dispatch2、traffic、lifecycle、feeds、resources）。`config.toml` 与 `config.example.toml` 靠手工同步（本轮同步了十次）。装载时没有校验：键名打错静默用缺省。

**B3 假设没有总账（中）**
25 处模拟 / 假设分散在配置和载荷里，回答里逐条说明，但没有一个接口能列出「当前这个答案依赖哪些假设」。演示时观众容易把 466 个「推演积水点」当成事实——虽然文字上写了，结构上没有。

### C. 安全

**C1 口令进日志（中，局域网内低）**
单一共享口令，走 `?key=` 查询串；`serve.err.log` 里 147 行明文含口令；控制台生成的深链接也带口令。Cookie 没有 `HttpOnly`；服务是 HTTP、设了口令就绑 `0.0.0.0`。PoC 局域网可接受，出网不行。`POST /api/feed/*` 凭同一口令就能写入记录，有追加式日志但没有身份。

**C2 客户数据出境到云端模型（决策项）**
规划器缺省走 DeepSeek 官方 API，提示词里带热点名称、位置、数字。需要 DMT 对数据分级做决定；技术上已留 `[agent.dsh].provider` 换本地或获批端点的口子。feeds 里的自由文本（报案备注）会进摘要再进模型，有提示注入面，但动作层是只读为主、写只到 `out/`，风险可控。

### D. 质量与流程

**D1 只有合成测试（中）**
139 个用例都是小夹具，跑 4.6 秒，好；但没有一条测试装载真实 `out/state` 跑服务接口。真机验证全靠本轮手工 curl 脚本，不可重复。9 个模块零测试引用。没有 CI、没有 lint / 类型检查、没有覆盖率。

**D2 可观测性弱（低）**
日志靠 `print`，没有级别、没有结构化字段；接口耗时只有载荷里的 `computed_ms`。动作日志 `out/ontology_actions.jsonl` 是好的开头。

**D3 依赖不锁定（低）**
Python 3.14 与 pandas 3.0 都很新；`>=` 下界意味着换机器可能装到不同版本；ortools 可选但行为差异（CP-SAT 与贪心）没有在结果里明显标出。

## 4. 建议

### 近期（1–2 周，不改总体结构）

1. **算过的东西落盘**：情景上下文、调度载荷、世界模型对照按 `(配置哈希, 状态清单, 代码提交)` 键写到 `out/cache/`，启动时直接读；预热变成可选的后台补算。目标：重启后 30 秒可用。
2. **长任务出锁**：求解走 `ProcessPoolExecutor`（绕开 GIL），HTTP 返回任务 id，`/api/jobs/<id>` 查进度，页面轮询；`self.lock` 只保护缓存写入。顺带解决 A2 的卡死。
3. **拆 serve.py**：路由表 + `api/` 下按域分文件（dispatch、lifecycle、feeds、ontology），统一参数解析与错误码，生成一份接口清单文档。
4. **口令不进日志**：覆写 `log_message` 打码查询串；控制台链接改用 cookie；加 `HttpOnly`；README 写清「仅局域网」。
5. **配置单一来源**：装载时按一份声明校验（类型、范围、必填），`config.example.toml` 由脚本从 `config.toml` 脱敏生成，删掉代码里重复的 DEFAULTS 或让它们从同一份声明来。
6. **锁依赖 + 最小 CI**：`pip freeze` 出锁文件；一个本地脚本或 GitHub Action 跑 `pytest`、`node --check`、`python -m swbrain.ontology --check`。
7. **一条真实集成测试**：用 `run.py` 在一小块管网上生成迷你 `out/state` 夹具入库（几 MB），测试里起服务、打 30 个接口各一次。

### 中期（1–2 个月）

8. **拆 runtime.py**：动作按域分文件，用装饰器注册；摘要改模板（中英各一份文本模板，数据填空），规则的逻辑说明从规则函数的 docstring 生成，消灭两份口径。
9. **控制台模块化**：拆成 ES 模块（地图、三道页、对话卡片、本体页、词典），加 jsdom 级别的卡片渲染测试；只有在功能再翻倍时才考虑换框架。
10. **假设总账**：一个接口列出当前情景 / 当前回答依赖的全部模拟输入（资源、桥、承包商、路况、雨量缺省、历史经历来源），页面顶部常驻一条「本页有 N 项假设」。
11. **契约正式化**：`exchange/schemas/*.json`（JSON Schema）+ `jsonschema` 校验，版本字段用起来；状态清单 `out/state/manifest.json`（源表行数、配置哈希、提交号），服务发现不匹配就拒绝装载。

### 远期（进入运行阶段前）

12. **拆服务**：批处理、求解、本体 / API、智能体网关四个进程；算过的状态和生命周期记录放进输出库 `sw_brain`（已经有），替代 jsonl，支持多用户与审计。
13. **身份与传输**：反向代理上 HTTPS，角色（值班、顾问、承包商）与操作审计，替代共享口令。
14. **模型端点**：按 DMT 的数据分级决定云端 / 本地模型；提示词里的客户字段可做脱敏映射。

- 只评审了架构与工程实践，没有评审水力学和调度模型的科学正确性（另见 `可信度说明.md`）。
